# BUG-001 Unverified rider can accept an open ride

**Controlled defect in local demo application**

| Field | Value |
| --- | --- |
| Bug ID | BUG-001 |
| Related requirement | REQ-004 Rider verification, supported by REQ-003 and REQ-007 |
| Related manual test | TC-011 Deny browsing and acceptance to unverified and pending riders |
| Severity | S1 Critical. The assignment bypasses rider approval, a prerequisite for carrying passengers. |
| Priority | P0 Immediate. Restore the server-side gate before relying on rider eligibility. |

## Environment

CampusRide QA Lab Phase 3 on Windows, Python 3.11.5, pytest 9.2.0, and temporary SQLite. The observed failure used FastAPI TestClient with a loopback ASGI address and `DEMO_BUG_MODE=true`.

## Preconditions

Use a fresh demo seed. Mira is a passenger with no rider verification. Ride #5 is Anika's unassigned regular request. Keep the two accounts in separate sessions.

## Reproduction steps

1. Start the [local lab](../docs/DEFECT-INVESTIGATION.md#start-a-local-investigation) with defect mode enabled.
2. Sign in as Mira. Read `GET /api/auth/me` and confirm that Mira only has the passenger role and that `verification_status` is `null`.
3. As Mira, call `POST /api/rides/5/accept`.
4. As Anika, read `GET /api/rides/5` and record the returned status and rider.

## Expected result

Acceptance returns HTTP `403`. Anika still sees the ride as `requested` with `rider_name: null`.

## Actual result

Acceptance returned HTTP `200`. Anika's separate read showed `accepted` with Mira Rahman assigned. The unverified account still received `403` when listing available rides.

## Confirmed root cause

The acceptance service calls the student-only access check on the lab branch. That check permits Mira to reach the assignment update without evaluating rider approval. [Acceptance service](../app/services/rides.py)

## Recommended fix

Require an approved rider in the acceptance service before attempting the conditional assignment. Retain the existing state and eligibility predicates that govern which ride can be assigned.

## Evidence references

See `test_bug_001_requires_rider_approval` in the [defect-mode output](../reports/bug-lab/03-defect-mode.txt) and [corrected-mode output](../reports/bug-lab/04-corrected-mode.txt).

## Verification status

Reproduced with defect mode on. With the mode off, the same test verified HTTP `403` and an unchanged ride assignment.
