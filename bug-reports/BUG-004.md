# BUG-004 Ride detail exposes a mock passenger phone number

**Controlled defect in local demo application**

| Field | Value |
| --- | --- |
| Bug ID | BUG-004 |
| Related requirement | REQ-014 Privacy |
| Related manual test | TC-031 Limit available-ride fields and restrict participant details |
| Severity | S1 Critical. The equivalent response with real contact data would disclose information outside the ride-detail contract. |
| Priority | P0 Immediate. Restore the approved response fields before exposing ride details. |

## Environment

CampusRide QA Lab Phase 3 on Windows, Python 3.11.5, pytest 9.2.0, and temporary SQLite. The observed failure used FastAPI TestClient with a loopback ASGI address and `DEMO_BUG_MODE=true`. The only phone value in the exercise is the fixed fictional string `000-000-0104`.

## Preconditions

Fresh ride #4 is assigned to Tariq and requested by Mira. Tariq is an authorized participant. Sami is outside this trip.

## Reproduction steps

1. Start the [local lab](../docs/DEFECT-INVESTIGATION.md#start-a-local-investigation) with defect mode enabled.
2. As Sami, verify that `GET /api/rides/4` returns HTTP `404`.
3. As Tariq, read `GET /api/rides/4` and inspect the JSON response for contact fields.

## Expected result

Tariq receives HTTP `200` with the allowed ride detail fields, including the passenger name. The JSON omits `passenger_phone`.

## Actual result

Sami received HTTP `404`. Tariq received HTTP `200` with `"passenger_phone":"000-000-0104"` in the JSON.

## Confirmed root cause

The lab branch appends the synthetic phone field after projecting `RideDetail`. It then returns a raw JSON response, so the typed response model does not filter the extra field. [Lab detail serializer](../app/bug_lab.py)

## Recommended fix

Return the typed `RideDetail` projection for authorized reads and check the resulting HTTP payload for unexpected contact fields. Keep the participant access check in place.

## Evidence references

See `test_bug_004_omits_phone_from_ride_details` in the [defect-mode output](../reports/bug-lab/03-defect-mode.txt) and [corrected-mode output](../reports/bug-lab/04-corrected-mode.txt).

## Verification status

Reproduced with defect mode on. With the mode off, Tariq received the permitted ride details and the mock field was absent.
