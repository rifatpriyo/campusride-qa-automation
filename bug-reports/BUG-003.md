# BUG-003 A rating is visible before the second participant submits

**Controlled defect in local demo application**

| Field | Value |
| --- | --- |
| Bug ID | BUG-003 |
| Related requirement | REQ-012 Ratings |
| Related manual test | TC-028 Reveal received ratings only after both participants submit |
| Severity | S2 High. Early disclosure undermines the privacy and independence of ratings. |
| Priority | P1 Current cycle. A revealed score can influence the second submission. |

## Environment

CampusRide QA Lab Phase 3 on Windows, Python 3.11.5, pytest 9.2.0, and temporary SQLite. The observed failure used FastAPI TestClient with a loopback ASGI address and `DEMO_BUG_MODE=true`.

## Preconditions

Start with fresh ride #3, which is in progress with Sami as passenger and Tariq as rider. Both start confirmations already exist. Neither participant has completed the ride or submitted a rating. Use separate sessions for Sami and Tariq.

## Reproduction steps

1. Start the [local lab](../docs/DEFECT-INVESTIGATION.md#start-a-local-investigation) with defect mode enabled.
2. Confirm completion for ride #3 as Tariq and as Sami using `POST /api/rides/3/complete`. Confirm the ride is `completed`.
3. As Sami, submit `{"score":5}` to `POST /api/rides/3/rating`.
4. Before Tariq submits a rating, read `GET /api/rides/3` in Tariq's session. Inspect `my_rating` and `received_rating`.

## Expected result

Tariq's details return `my_rating: null` and `received_rating: null`. Each participant can see the received score after both have submitted.

## Actual result

Tariq's read returned HTTP `200` with `my_rating: null` and `received_rating: 5`.

## Confirmed root cause

The lab detail serializer replaces the masked `received_rating` with the other participant's stored score. It does not apply the two-submission rule to that field. [Lab detail serializer](../app/bug_lab.py)

## Recommended fix

Use the shared ride detail projection, which returns a received score only for a participant who has submitted a rating and has a counterpart score. Test the response before and after the second submission.

## Evidence references

See `test_bug_003_keeps_a_single_rating_private` in the [defect-mode output](../reports/bug-lab/03-defect-mode.txt) and [corrected-mode output](../reports/bug-lab/04-corrected-mode.txt).

## Verification status

Reproduced with defect mode on. With the mode off, the first rating stayed hidden from Tariq until Tariq submitted, after which each participant received the other's score.
